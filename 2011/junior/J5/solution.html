官方题目PDFDMOJ

题目在问什么

计算 Mark 不删除自己的前提下，有多少种不同的删除人员集合。

考查知识点

  • 邀请关系可以画成一棵树：例如 4 邀请 3，3 邀请 1，就画出 4 → 3 → 1。直接被某人邀请的人是他的孩子；这个人自己，加上从他沿邀请关系往下到达的所有人，组成他的子树。
  • 乘法原理：若两个互不相连的分支分别有 a、b 种合法选择，合起来就有 a×b 种。例如两名叶子各自可选删或不删，合计 2×2=4 种。
  • 递归计数：先数更小的子树，再把结果合起来。设 F(v) 是以 v 为根的子树中合法删除方案数；保留 v 时，孩子子树可独立选择，方案数是各 F(child) 的乘积；删除 v 时必须删除整个子树，只有 1 种。因此 F(v)=1+各孩子方案数的乘积。

一步一步想

  1. 按题目给出的父子关系建立孩子列表。输入中每行给出一个人的邀请者，所以把这个人放进邀请者的孩子列表。
  2. 对一个人 v，先递归计算每个孩子子树的方案数，并将这些数相乘，表示保留 v 时的选择。
  3. 再加 1，表示删除 v 并连同子树里所有人一起删除的唯一方案。叶子没有孩子，孩子方案数的乘积为空乘积 1，所以叶子的 F 值是 2：删或不删。
  4. Mark 是编号 N 的根且不能删除；答案只把他的各个孩子子树方案数相乘，不使用 F(Mark) 中“删除 Mark”的额外方案。

用例子走一遍

样例 2 中，4 是 Mark，4 邀请 2 和 3，3 邀请 1。人 1 有 2 种选择，所以 F(3)=1+2=3；人 2 也有 2 种选择。Mark 保留，两个分支独立，答案为 2×3=6。

为什么这样做是对的

对任意非 Mark 的人 v，合法删除集合恰好分成两类：保留 v，或删除 v。若保留 v，题目没有规定必须删除邀请者，因此每个孩子子树都能独立选一个合法集合，组合数是各孩子 F 值的乘积；若删除 v，规则强制删除整棵子树，恰好形成一种集合。两类分别包含和不包含 v，不会重复，因此 F(v)=1+各孩子 F 值的乘积。叶子时该式给出两种选择，向上递归就能正确计数每个子树。根是不能删除的 Mark，故只需组合他的孩子子树选择，所得正是所有合法集合数。

运行时间与内存

每个人只在递归中访问一次，每条父子关系也只在乘积中处理一次，时间为 O(N)，意思是人数增长时工作量也按相同的比例增长。孩子列表和递归调用最多保存 O(N) 个关系与调用，空间也随人数增长。题目 N≤6，最多只有六层递归。

容易出错的地方

  • 边的方向要从邀请者指向被邀请者；删除邀请者会强制删除孩子，但删除孩子不会强制删除邀请者。
  • 保留某人时，仍可以独立删除他的孩子分支；不要误认为必须先删除邀请者。
  • Mark 是根且不能删除，最终答案不能包含“删除根”的那 1 种方案。
  • 空集合也是一种合法方案；乘积没有孩子时按 1 计算。

Python 3 解法

solution.py
from math import prod
import sys


def ways(person, children):
    return 1 + prod(ways(child, children) for child in children[person])


def main():
    data = list(map(int, sys.stdin.buffer.read().split()))
    n = data[0]
    children = [[] for _ in range(n + 1)]
    for person, parent in enumerate(data[1:], 1):
        children[parent].append(person)

    print(prod(ways(child, children) for child in children[n]))


if __name__ == "__main__":
    main()

Problem statement (English)
Problem J5: Unfriend
Problem Description
Mark invited some people to join his social network. Some of them invited new people, who
invited new people, and so on. Now there are N people in the network, numbered from 1 to N .
Mark has decided to remove some people and keep others. There is one restriction: when removing
a person, he will also remove the people s/he invited, and the people they invited, and so on. Mark
will never remove himself, and we do not allow people to be invited by more than one person.
Mark can also decide to not remove anyone.
How many different sets of people can be removed?
Input Specification:
The first line contains a single integer N (N ≤ 6), the number of people in the network. Next are
N − 1 lines telling us who invited each person. To be precise, line i in this set (1 ≤ i ≤ N − 1)
contains a single integer j (with j > i), which indicates that person j is the person who invited
person i. Person N is Mark.
Output Specification:
Output a single integer, the number of possible sets of people that can be removed.

Sample Input 1
3
3
3

Output for Sample Input 1
4

Explanation for Sample 1
The first number of the input indicates there are three people in the network. The next line tells
us that Person 1 was invited by Mark, while the last line tells us that Person 2 was also invited by
Mark. The sets of people that can be removed are {}, {1}, {2}, {1,2}.

Official problemPDFDMOJ

What are we asked to do?

Count the different sets of people Mark can remove while keeping himself.

Knowledge and skills

  • The invitations form a tree. For example, if 4 invited 3 and 3 invited 1, draw 4 → 3 → 1. Someone invited directly by a person is that person's child; the person and everyone reached by following invitations downward form a subtree.
  • The multiplication rule combines independent choices: if two separate branches have a and b valid choices, together they have a×b choices. For example, two leaves can each be kept or removed, giving 2×2=4 choices.
  • Recursive counting solves smaller subtrees first and combines their answers. Let F(v) count valid removals in the subtree rooted at v. If v stays, each child subtree is chosen independently, giving the product of the child F values. If v is removed, the whole subtree must be removed, giving exactly 1 choice. Thus F(v)=1+the product of the child counts.

Think step by step

  1. Build a list of children from the input: each line names a person's inviter, so add that person to the inviter's child list.
  2. For a person v, recursively count the choices in each child subtree and multiply those counts. This is the number of choices when v stays.
  3. Add 1 for the single choice where v and everyone in the subtree are removed. A leaf has no children, so its empty product is 1 and F(v)=2: keep it or remove it.
  4. Mark is the root numbered N and cannot be removed. Multiply the counts for his child subtrees directly, without adding the choice that removes Mark.

Walk through an example

In sample 2, 4 is Mark, who invited 2 and 3, and 3 invited 1. Person 1 has 2 choices, so F(3)=1+2=3; person 2 also has 2 choices. Mark stays, and the branches are independent, giving 2×3=6.

Why does this work?

For any person v other than Mark, every valid removal set in v's subtree belongs to exactly one of two groups: v stays, or v is removed. If v stays, the rules do not require removing an inviter, so each child subtree can independently use any valid set; the number is the product of the child F values. If v is removed, the rule forces the entire subtree to be removed, giving exactly one set. These groups are disjoint because only the second contains v, so F(v)=1+the product of the child counts. For a leaf this gives the two choices, and applying the rule upward counts every valid set in each subtree. Since the root is Mark and cannot be removed, combining only his child subtrees gives exactly the number of allowed sets.

Time and memory

Each person is visited once, and each parent-child link is handled once in a product, taking O(N) time: the work grows in proportion to the number of people. The child lists and recursive calls use O(N) space, which also grows with the number of people. Since N≤6, there are at most six recursive levels.

Common mistakes

  • Point each relationship from inviter to invited person. Removing an inviter forces removal of the child; removing a child does not force removal of the inviter.
  • A person can stay while people in a child branch are removed; do not require removing the inviter first.
  • Mark is the root and must stay, so the final answer must exclude the one choice that removes the root.
  • The empty removal set is valid; a product with no children is 1.
