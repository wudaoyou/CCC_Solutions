2014 S2 · Assigning Partners

2014 / senior / S2

官方题目PDFDMOJ

题目在问什么

每一列给出两个姓名的搭档安排。合法安排必须让两人互为搭档，而且任何人都不能与自己搭档。用姓名到搭档的字典逐人检查这两个条件。

考查知识点

  • 对应位置表示一项安排。例如两行分别是 Ada Alan 和 Alan Ada，两列表示 Ada 与 Alan、Alan 与 Ada，所以两人互为搭档。N 表示学生人数。
  • 字典用一个键查到对应的值。这里键是姓名，值是同一列另一行的姓名。例如 partners['Ada']='John' 表示 Ada 在表格中对应 John。zip 把两行中相同位置的姓名组成一对。
  • 互为搭档表示沿着安排走两步会回到起点：Ada 对应 John，John 必须对应 Ada。只检查“搭档在班里”还不够，因为输入保证所有姓名都在两行中出现。
  • 自我搭档是姓名对应自己，例如 Jacob 对应 Jacob。虽然走两步也会回到自己，但题目明确禁止，所以要另外检查 name != partner。
  • 姓名区分大小写：A 和 a 可以是两名不同的学生。字符串原样作为字典的键，无需改成全大写或全小写。

一步一步想

  1. 读取 N 和输入第二、三行各 N 个姓名。用 zip 按列配对，建立第二行姓名到第三行对应姓名的字典 partners。
  2. 对字典中的每个 name 和 partner，先检查 name != partner，排除自我搭档。
  3. 再检查 partners[partner] == name，确认对方也指回当前学生。
  4. all 只有在所有学生都满足两个条件时才为真。此时输出 good；只要有人不满足，就输出 bad。

用例子走一遍

官方样例 1 的两行姓名是 Ada Alan Grace John 和 John Grace Alan Ada。字典记录 Ada→John、Alan→Grace、Grace→Alan、John→Ada。每个人都对应另一人，而且沿箭头走两步回到自己，所以输出 good。

官方样例 2 中 Graeme→Vlado，但是 Vlado→Rich，无法回到 Graeme；Jacob→Jacob 又违反不能自我搭档的规则，因此输出 bad。三人循环 A→B、B→C、C→A 同样不合法：走两步不能回到起点。

为什么这样做是对的

字典记录了输入每列的对应关系。若程序输出 good，那么对每名学生都检查过他与搭档不是同一人，而且搭档的对应姓名正是他。因此每项安排都由两名不同学生互相确认，满足题目的全部条件。反过来，若安排符合题意，每名学生的搭档都不是自己，并且对方也对应他，所以所有检查都会通过，程序会输出 good。因而程序恰好接受所有合法安排；其他安排至少违反一个检查，输出 bad。

运行时间与内存

建立字典和逐人检查都只遍历 N 名学生一次。把每个姓名看作固定大小时，字典查找平均为 O(1)，总时间平均为 O(N)，空间为 O(N)。若计入姓名字符，令 L 为输入中姓名字符的总数，则读入、姓名哈希与保存字符串也需要处理这些字符，平均时间和空间为 O(N+L)。N≤30，无需搜索所有配对方案。

容易出错的地方

  • 必须同时检查互为搭档和不能自我搭档；只满足其中一个条件仍可能是 bad。
  • 两行包含相同姓名不代表安排合法。这只是输入保证，并没有排除长度大于 2 的循环。
  • 不要分别排序两行：排序会破坏原来同一列的安排关系。
  • 不要忽略大小写；A 和 a 可以是不同学生。
  • 输出必须是小写的 good 或 bad。人数为奇数时无法全班分成互不重叠的两人组，这些检查自然会判为 bad。

Python 3 解法

solution.py
import sys


data = sys.stdin.read().split()
n = int(data[0])
partners = dict(zip(data[1:n + 1], data[n + 1:]))
good = all(name != partner and partners[partner] == name for name, partner in partners.items())
print("good" if good else "bad")

官方题目

官方题目原文为英文；图表和原版排版请看 PDF。

Problem statement (English)
Problem S2: Assigning Partners
Problem Description
The CEMC is organizing a workshop with an activity involving pairs of students. They decided
to assign partners ahead of time. You need to determine if they did this consistently. That is,
whenever A is a partner of B, then B is also a partner of A, and no one is a partner of themselves.

Input Specification
The input consists of three lines. The first line consists of an integer N (1 < N ≤ 30), which is
the number of students in the class. The second line contains the first names of the N students sep-
arated by single spaces. (Names contain only uppercase or lowercase letters, and no two students
have the same first name). The third line contains the same N names in some order, separated by
single spaces.
The positions of the names in the last two lines indicate the assignment of partners: the ith name
on the second line is the assigned partner of the ith name on the third line.

Output Specification
The output will be good if the two lists of names are arranged consistently, and bad if the ar-
rangement of partners is not consistent.

Sample Input 1
4
Ada Alan Grace John
John Grace Alan Ada

Output for Sample Input 1
good

Explanation for Output for Sample Input 1
Ada and John are partners, and Alan and Grace are partners. This arrangement is consistent.

Sample Input 2
7
Rich Graeme Michelle Sandy Vlado Ron Jacob
Ron Vlado Sandy Michelle Rich Graeme Jacob

Output for Sample Input 2
bad

Explanation for Output for Sample Input 2
Graeme is partnered with Vlado, but Vlado is partnered with Rich. This is not consistent. It is also
inconsistent because Jacob is partnered with himself.

Official problemPDFDMOJ

What are we asked to do?

Each column gives a proposed partner assignment. A valid arrangement requires two students to name each other, and nobody may be their own partner. Check both conditions with a dictionary from names to partners.

Knowledge and skills

  • Matching positions specify an assignment. For rows Ada Alan and Alan Ada, the columns give Ada with Alan and Alan with Ada, so the students are mutual partners. N denotes the number of students.
  • A dictionary looks up a value by its key. Here the key is a name and the value is the name in the same column of the other row. For example, partners['Ada']='John' records Ada's correspondence with John. zip combines names from matching positions into pairs.
  • Mutual partners point back to each other: if Ada corresponds to John, John must correspond to Ada. Following the correspondence twice must return to the starting student. Checking only that the partner is in the class is insufficient; the input already guarantees that both rows contain all the names.
  • A self-partner assignment has a name pointing to itself, such as Jacob to Jacob. It also returns to itself after two steps, so we need the separate check name != partner.
  • Names are case-sensitive: A and a can be two different students. Use the original strings as dictionary keys, without converting their case.

Think step by step

  1. Read N and the two rows of N names. Use zip to pair matching columns and create partners, mapping each name in the first name row to the corresponding name in the second name row.
  2. For each name and partner, check name != partner to reject self-partners.
  3. Also check partners[partner] == name to ensure the other student points back.
  4. all is true only when every student satisfies both conditions. Print good in that case; otherwise print bad.

Walk through an example

Official sample 1 has rows Ada Alan Grace John and John Grace Alan Ada. The dictionary records Ada→John, Alan→Grace, Grace→Alan, and John→Ada. Every student points to somebody else and returns to themselves after two steps, so the result is good.

In official sample 2, Graeme→Vlado but Vlado→Rich, so the correspondence does not return to Graeme. Jacob→Jacob also violates the no-self-partner rule. The result is bad. A three-student cycle A→B, B→C, C→A is also invalid: two steps do not return to the starting student.

Why does this work?

The dictionary records the correspondence in every input column. If the program prints good, it has checked that every student has a different partner and that this partner points back to the student. Thus every assignment is confirmed by two distinct students, satisfying both requirements. Conversely, in a valid arrangement each partner differs from the student and points back to them, so every check succeeds and the program prints good. The program therefore accepts exactly the valid arrangements; any other arrangement fails at least one check and produces bad.

Time and memory

Building the dictionary and checking it each visit N students once. Treating each name as a fixed-size value, dictionary lookups take O(1) time on average, so total time is O(N) on average and space is O(N). If name lengths are included, let L be the total number of name characters in the input. Reading, hashing, and storing those characters gives average time and space O(N+L). With N≤30, there is no need to search through possible pairings.

Common mistakes

  • Check both mutual assignments and the absence of self-partners. Either condition alone can accept an invalid arrangement.
  • Both rows containing the same names does not prove validity. That input guarantee still allows cycles longer than two students.
  • Do not sort the rows separately: sorting destroys the correspondence between their columns.
  • Preserve letter case; A and a can be different students.
  • Print lowercase good or bad. An odd-sized class cannot split into disjoint two-person groups; these checks naturally reject such an arrangement.
