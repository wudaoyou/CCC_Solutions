2010 S2 · Huffman Encoding

2010 / senior / S2

官方题目PDFDMOJ

题目在问什么

输入已经给出每个字母的二进制编码。我们要把一条二进制消息还原成字母，不需要根据频率设计编码，也不需要构造霍夫曼树。

考查知识点

  • 前缀：字符串开头的一段。例如，01 是 011 的前缀，但 10 不是。
  • 无前缀编码：任何字母的完整编码都不是另一个字母编码的前缀。例如，0 和 10 可以同时出现，0 和 01 则不可以。
  • 字典：以二进制编码作为键、字母作为值，方便查找当前读到的编码。
  • 贪心解码：从左到右读位，第一次遇到完整编码就立即取出对应字母。

一步一步想

  1. 读入 k 行编码表，将每一行的“字母 编码”反过来存成 codes[编码] = 字母。
  2. 创建空字符串 current，记录上一次解码之后读到的位；创建列表 decoded，记录已还原的字母。
  3. 逐位读取消息，将该位接在 current 后面。
  4. 如果 current 是字典中的完整编码，就把对应字母加入 decoded，并将 current 清空，从下一个字母重新开始。
  5. 所有位读完后，用 join 拼接 decoded，输出一行。题目保证消息有效，因此结尾不会剩下不完整编码。

用例子走一遍

官方样例的编码是 A=00、B=01、C=10、D=110、E=111。读取 00000101111 时，第一个 0 还不完整，再读一个 0 得到 00，输出 A 并清空 current。依次得到 00|00|01|01|111，还原为 AABBE。最后一段长度是 3，其余段长度是 2，所以不能固定长度切分。

为什么这样做是对的

设下一字母的实际编码为 c。在 c 读完之前，current 是 c 的真前缀。它不可能是另一个完整编码，否则会违反无前缀性质。读完 c 时，字典一定匹配到它；它也不可能是更长编码的前缀，所以立即取出该字母是正确的。清空 current 后，剩余消息仍从下一个字母的编码开始。重复这一过程，就能正确且唯一地还原整条消息。

运行时间与内存

设 k 为编码数，b 为最长编码长度，L 为消息位数。建表需要 O(kb) 时间；每次拼接字符串和查字典最多处理 b 位，因此扫描需要 O(Lb) 时间，总时间 O(kb + Lb)。字典占 O(kb)，消息和结果占 O(L)，总空间 O(kb + L)。题目中 k≤20、b≤10、L≤250，这种简单扫描足够快。

容易出错的地方

  • 编码长度可能不同，不能按固定的两位或三位切分消息。
  • 字典应当从编码查到字母，而不是从字母查到编码。
  • 匹配一个完整编码后必须清空 current，否则下一字母会接到上一编码后面。
  • 大小写是输入的一部分，不能把所有字母转成大写或小写。
  • 题目给的是编码表，解码无需构造树，也无需计算字母频率。

Python 3 解法

solution.py
import sys


count = int(sys.stdin.readline())
codes = {}
for _ in range(count):
    character, code = sys.stdin.readline().split()
    codes[code] = character

message = sys.stdin.readline().strip()
current = ""
decoded = []
for bit in message:
    current += bit
    if current in codes:
        decoded.append(codes[current])
        current = ""

print("".join(decoded))

Problem statement (English)
Problem S2: Huffman Encoding
Problem Description
There is an ingenious text-compression algorithm called Huffman coding, designed by David Huff-
man in 1952.
The basic idea is that each character is associated with a binary sequence (i.e., a sequence of 0s and
1s). These binary sequences satisfy the prefix-free property: a binary sequence for one character is
never a prefix of another character’s binary sequence.
It is worth noting that to construct a prefix-free binary sequence, simply put the characters as the
leaves of a binary tree, and label the “left” edge as 0 and the ”right” edge as 1. The path from the
root to a leaf node forms the code for the character at that leaf node. For example, the following
binary tree constructs a prefix-free binary sequence for the characters {A, B, C, D, E}:




That is, A is encoded as 00, B is encoded as 01, C is encoded as 10, D is encoded as 110 and E is
encoded as 111.
The benefit of a set of codes having the prefix-free property is that any sequence of these codes
can be uniquely decoded into the original characters.
Your task is to read a Huffman code (i.e., a set of characters and associated binary sequences)
along with a binary sequence, and decode the binary sequence to its character representation.

Input Specification
The first line of input will be an integer k (1 ≤ k ≤ 20), representing the number of characters and
associated codes. The next k lines each contain a single character, followed by a space, followed
by the binary sequence (of length at most 10) representing the associated code of that character.
You may assume that the character is an alphabet character (i.e., ‘a’...‘z’ and ‘A’..‘Z’). You may
assume that the sequence of binary codes has the prefix-free property. On the k + 2nd line is the
binary sequence which is to be decoded. You may assume the binary sequence contains codes
associated with the given characters, and that the k + 2nd line contains no more than 250 binary
digits.

Official problemPDFDMOJ

What are we asked to do?

The input already supplies a binary code for each letter. Decode a binary message into letters; there is no need to design codes from frequencies or construct a Huffman tree.

Knowledge and skills

  • Prefix: a beginning part of a string. For example, 01 is a prefix of 011, but 10 is not.
  • Prefix-free codes: no complete letter code is a prefix of another letter's code. Codes 0 and 10 may coexist; codes 0 and 01 may not.
  • Dictionary: use binary codes as keys and letters as values to look up the code read so far.
  • Greedy decoding: read bits from left to right and consume a code as soon as it is complete.

Think step by step

  1. Read the k codebook lines. Reverse each letter-code pair when storing it: codes[code] = character.
  2. Start with an empty string current for bits read since the previous match, and a list decoded for recovered letters.
  3. Read the message one bit at a time, appending that bit to current.
  4. When current is a dictionary key, append its letter to decoded and clear current to begin the next letter.
  5. After all bits have been read, join decoded and print one line. The input guarantees a valid message, so no incomplete code remains.

Walk through an example

The official sample uses A=00, B=01, C=10, D=110, E=111. For 00000101111, the first 0 is incomplete; the next 0 completes 00, so append A and clear current. Continuing gives 00|00|01|01|111 and the output AABBE. The final code has length 3 while the others have length 2, so fixed-size splitting would fail.

Why does this work?

Let c be the actual code of the next letter. Before all of c is read, current is a proper prefix of c. It cannot be another complete code, because that would violate prefix-freeness. When c is complete, it must match the dictionary, and it cannot be the prefix of a longer code. Consuming its letter immediately is therefore correct. After clearing current, the remaining message starts with the next letter's code. Repeating this argument decodes the entire message correctly and uniquely.

Time and memory

Let k be the number of codes, b the maximum code length, and L the message length in bits. Building the dictionary takes O(kb) time. Each string append and dictionary lookup handles at most b bits, so scanning takes O(Lb) time, for O(kb + Lb) total. The dictionary uses O(kb) space and the message and output use O(L), for O(kb + L) total space. With k≤20, b≤10, and L≤250, this simple scan is fast enough.

Common mistakes

  • Code lengths may differ; do not split the message into fixed two-bit or three-bit chunks.
  • The dictionary must map codes to letters, not letters to codes.
  • Clear current after every complete match, or the next letter's bits will remain attached to the previous code.
  • Letter case is part of the input; preserve both uppercase and lowercase letters.
  • The codebook is supplied. Decoding needs neither a tree nor frequency calculations.
