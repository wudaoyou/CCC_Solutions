2015 J4 · Wait Time

2015 / junior / J4

官方题目PDFDMOJ

题目在问什么

按消息出现的先后记录时间；每个朋友的 R 开始一段等待，匹配的 S 结束等待并把秒数加到总和。最后仍在等待的朋友输出 -1。

考查知识点

  • 时间线：把第一条消息的时刻定为 0。相邻两条消息之间没有 W 时经过 1 秒；有 W x 时经过 x 秒，x 已经替代这 1 秒，不要再多加 1。
  • 字典可以按朋友编号保存信息。pending 记录每位朋友尚未回复的消息时刻，waits 记录已经完成的等待秒数。朋友不能在收到回复前再发下一条，所以同一朋友最多有一条未回复消息。
  • 一次扫描：从左到右读每条记录，只更新当前时刻、等待中的消息和总等待时间。扫描一遍就能处理完全部记录。
  • 排序：字典不保证题目要求的输出顺序，因此最后把出现过的朋友编号从小到大排列后输出。

一步一步想

  1. 读入 M 条记录。把第一条 R 或 S 的时刻设为 0；把下一段消息间隔先设为默认的 1 秒。
  2. 读到 W x 时，把下一段消息间隔改成 x 秒。它替代默认的 1 秒，只对紧接着的下一条消息生效。
  3. 读到 R X 时，先按上一段间隔更新时刻，再把朋友 X 的收到时刻存入 pending。若 X 首次出现，把累计等待设为 0；否则保留之前已累计的时间。
  4. 读到 S X 时，先更新时刻，再用当前时刻减去 pending[X]，累加到 waits[X]，然后清除这条待回复记录。
  5. 处理完所有记录后，按朋友编号排序。若朋友还在 pending 中，输出 -1；否则输出其已完成等待时间的总和。

用例子走一遍

官方样例 1：记录为 R 2、R 3、W 5、S 2、S 3。第一条消息时刻是 0；第二条因没有 W，在时刻 1 收到。W 5 表示下一条消息与前一条相隔 5 秒，所以 S 2 在时刻 6，S 3 因没有 W 在时刻 7。朋友 2 等了 6 秒，朋友 3 也等了 6 秒，输出 2 6 和 3 6。W 5 已包含这段间隔，不是 1+5 秒。

为什么这样做是对的

在每条消息前，now 等于题目记录的实际时刻：第一条消息时刻为 0；之后若有 W，就加 W 的秒数，否则加 1 秒。读到 R 时，程序保存该消息的时刻。根据题目规则，同一朋友在收到回复前不会再发消息，因此 pending 中保存的正是该朋友目前唯一需要回复的消息。读到 S 时，当前时刻减去保存时刻恰好是这条消息的等待时间，程序将它加进该朋友的总和并删除待回复记录。逐条处理后，每个朋友的总和正好包含其所有已回复消息的等待时间；最后仍在 pending 中的朋友恰有未回复消息，应输出 -1。排序只改变输出顺序，不改变这些结果。

运行时间与内存

设 M 为记录数，F 为出现过的朋友数。程序读取并处理每条记录一次，最后排序朋友编号，因此时间为 O(M + F log F)。字典保存每位朋友的等待总和和待回复时刻；分词后的输入占 O(M)，所以总空间为 O(M + F)。 F log F 描述排序的工作量，比把每对朋友都比较一次的 F² 增长慢。本题最多 20 条记录、100 个朋友编号，直接处理足够快。

容易出错的地方

  • W x 是下一对消息之间的完整间隔，使用 x 秒；不能把它当成默认 1 秒之外的额外时间。
  • 第一条消息从时刻 0 开始。不要在它之前再加默认的 1 秒。
  • R 是收到朋友发来的消息，S 是回复朋友；等待从 R 开始，在对应的 S 结束。
  • 只要某朋友最后还有未回复消息，该朋友的总结果就是 -1，即使之前已经有几次回复。
  • 按朋友编号升序输出；不要按他们发消息或回复的先后排序。

Python 3 解法

solution.py
import sys


def solve(data):
    tokens = data.split()
    if not tokens:
        return ""

    count = int(tokens[0])
    now = 0
    have_message = False
    next_gap = 1
    waits = {}
    pending = {}

    for i in range(count):
        kind = tokens[1 + 2 * i]
        friend = int(tokens[2 + 2 * i])
        if kind == b"W":
            next_gap = friend
            continue

        if have_message:
            now += next_gap
        have_message = True
        next_gap = 1

        if kind == b"R":
            waits.setdefault(friend, 0)
            pending[friend] = now
        else:
            waits[friend] += now - pending.pop(friend)

    return "".join(
        f"{friend} {-1 if friend in pending else waits[friend]}\n"
        for friend in sorted(waits)
    )


if __name__ == "__main__":
    sys.stdout.write(solve(sys.stdin.buffer.read()))

Problem statement (English)
Problem J4: Wait Time
Problem Description
You exchange text messages with your friends. Since you receive so many messages, you want to
measure how long your friends have to wait for your replies.
Your message device records each received and sent message in order using the following two
kinds of entries:

   • R X indicates a message was received from a friend numbered X;
   • S X indicates a message was sent to a friend numbered X.

Your message device sends and receives messages instantaneously, and for each consecutive pair
of entries described above, either

   • a single entry W X is recorded in between them indicating they occur X seconds apart, or
   • there is no entry between them and they occur one second apart.

Several rules of message etiquette are always followed:

   • the only messages you send are replies to messages that you have received;
   • you send at most one reply to any message from any particular friend;
   • your friends do not send a subsequent message until you have replied to their previous mes-
     sage.

The wait time for a message is the time that passes between when you receive it and the time you
reply to it. If a friend X received a reply to each message they sent, the total wait time for friend
X is the sum of all wait times for all messages from friend X. Otherwise, the total wait time for
friend X is −1.
Your job is to determine the total wait time for each friend.

Input Specification
The input consists of the integer M (1 ≤ M ≤ 20), followed by M lines, where each line consists
of one character (W, R, or S), followed by a space, followed by an integer X (1 ≤ X ≤ 100). These
M lines are the entries described above (in order).

Output Specification
Output one line for each friend that sent a message in the form X T where X is a friend number
and T is the total wait time for friend X. The lines are in increasing order of the friend numbers.

Official problemPDFDMOJ

What are we asked to do?

Track the time of each message. An R starts a friend's wait; its matching S ends that wait and adds the elapsed seconds to the total. Print -1 for any friend who still has an unanswered message.

Knowledge and skills

  • A timeline: Set the first message's time to 0. Consecutive messages are 1 second apart when there is no W; W x means they are x seconds apart, replacing that default second.
  • A dictionary can store information by friend number. pending stores the time of each unanswered message, and waits stores completed wait time. A friend cannot send again before getting a reply, so they have at most one unanswered message.
  • One pass: Read the records from left to right, updating the current time, pending messages, and totals. Each record needs to be processed only once.
  • Sorting: A dictionary does not promise the output order required by the problem, so sort the friend numbers before printing.

Think step by step

  1. Read the M records. Set the first R or S message's time to 0, and start with a default gap of 1 second before the next message.
  2. When W x appears, set the next message gap to x seconds. It replaces the default second and applies only to the next message.
  3. For R X, first advance the clock using the last gap, then save the time in pending for friend X and set X's total wait to 0 if needed.
  4. For S X, first advance the clock, then add the current time minus pending[X] to waits[X] and remove that pending message.
  5. After all records, sort the friend numbers. Print -1 if a friend is still in pending; otherwise print the completed total wait.

Walk through an example

Official sample 1 has R 2, R 3, W 5, S 2, S 3. The first message is at time 0; with no W, the second is at time 1. W 5 says the next message is 5 seconds after the previous one, so S 2 is at time 6. With no W after that, S 3 is at time 7. Friend 2 waited 6 seconds and friend 3 also waited 6 seconds, so print 2 6 and 3 6. W 5 already gives the full gap; it is not 1+5 seconds.

Why does this work?

Before each message, now is its correct time: the first message is at time 0, and every later message advances by W's value when W is present or by 1 otherwise. When an R appears, the program saves its time. By the problem rules, that friend cannot send another message before receiving a reply, so pending holds exactly the one message that needs a reply. At S, subtracting the saved time from the current time gives that message's wait, which the program adds to the friend's total before removing the pending entry. Thus each total contains exactly the waits of all answered messages. Any friend still in pending has an unanswered message and must receive -1. Sorting changes only output order, not the computed values.

Time and memory

Let M be the number of records and F the number of friends who appear. The program processes each record once and sorts the friend numbers, for O(M + F log F) time. The dictionaries use O(F) space, and splitting the input uses O(M), for O(M + F) total space. F log F describes the sorting work and grows more slowly than comparing every pair, which takes F² checks. There are at most 20 records and 100 possible friend numbers, so direct processing is easily fast enough.

Common mistakes

  • W x is the whole gap to the next message. Use x seconds; do not add it on top of the default second.
  • The first message starts at time 0. Do not add a default second before it.
  • R means a message arrived from a friend; S is the reply. The wait begins at R and ends at its matching S.
  • If a friend has any unanswered message at the end, that friend's result is -1 even if earlier messages were answered.
  • Print friends in increasing numerical order, not in message or reply order.
