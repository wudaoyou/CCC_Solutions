2013 S3 · Chances of winning

2013 / senior / S3

官方题目PDFDMOJ

题目在问什么

四支队伍两两各赛一场。根据已赛结果，统计剩余比赛所有胜、负、平组合中，目标队最终积分严格超过另外三队的组合数。题目要求计数，不要求计算概率。

考查知识点

  • 比赛比分和联赛积分不同：比分只用来判断胜负。即使以 100:99 获胜，胜方也只得 3 积分，负方得 0；2:2 平局则双方各得 1 分。不能把进球数直接加到积分表。
  • 四支队伍的无序两两组合是 (1,2)、(1,3)、(1,4)、(2,3)、(2,4)、(3,4)，一共六场。这里组合不区分先后，例如 (1,2) 和 (2,1) 是同一场。程序用 combinations 生成这六对，再排除已赛场次。
  • 每场未赛比赛只有三种积分结果：左队胜为 (3,0)，右队胜为 (0,3)，平局为 (1,1)。两场比赛共有 3×3=9 种结果组合；r 场共有 3^r 种。枚举就是逐一检查这些完整组合，而不是猜每场最有利的结果。
  • 笛卡尔积是从每一组选择中各取一个，形成所有可能的组合。例如两场的“胜、负、平”选择会组成九个结果对。Python 的 product(..., repeat=r) 逐个生成 r 场的完整结果，不必一次存下全部 3^r 个组合。
  • 严格第一表示目标队积分必须比每个对手都多。例如目标队 7 分、另一队也是 7 分，即使其余队伍更低，仍不算冠军。all(...) 用来检查三个比较是否全部成立。

一步一步想

  1. 读入目标队 T 和已赛 G 场。积分表按队号 1 到 4 保存，初始全为 0；程序的下标 0 留空不用。
  2. 处理已赛比赛：比较 SA 与 SB，给胜方加 3，或平局双方各加 1。记录已赛的队伍对。
  3. 生成四队的全部六个队伍对，并去掉已经比赛的，得到 r=6−G 场未赛比赛。
  4. 用 product 枚举每场 (3,0)、(0,3)、(1,1) 的所有组合。每次都复制已赛积分表，确保不同组合互不影响。
  5. 把当前组合分配的积分逐场加到副本上。然后比较目标队与另外三队；若三个严格大于比较都成立，答案加 1。
  6. 所有组合检查结束后输出计数。不同具体比分只要胜负平相同，就属于同一种积分结果，不要重复计数。

用例子走一遍

样例 2 的已赛积分为队 1 得 1 分、队 2 得 2 分、队 3 得 6 分、队 4 得 1 分。剩余比赛是 (1,4) 和 (2,3)。队 1、2、4 即使赢下自己的最后一场，也最多分别有 4、5、4 分；目标队 3 即使输掉，也仍有 6 分。因此两场比赛各自三种结果的 3×3=9 个组合全部合格，输出 9。

再看一个只剩 (1,2) 的例子：当前积分为 [6,6,1,1]，目标是队 1。若队 1 胜，最终为 [9,6,1,1]，算一次；若队 2 胜，队 1 不是第一；若平局，最终为 [7,7,1,1]，也不合格。因此答案是 1。

为什么这样做是对的

首先，已赛每场比较实际比分，按规则加上胜方 3 分或双方各 1 分，所以初始积分表准确。每对队伍只赛一次，生成全部六对并去掉已赛场次后，剩余列表恰好包含全部未赛比赛。

其次，每场未赛比赛的积分结果恰好是三种之一。product 为每场选择一种结果，且每个完整结果序列只生成一次，因此没有遗漏或重复。对每个序列，从已赛积分的副本出发，把每场所选积分加上，得到的正是该序列下的最终积分。复制表确保别的序列不会留下额外积分。

最后，目标队严格超过三个对手，当且仅当它是唯一积分最高的队伍。程序只在这三个比较全部成立时计数，排除了所有并列情况。全部可能序列都恰好检查一次，所以累计值就是题目要求的冠军结果数。

运行时间与内存

令 r=6−G≤6。处理已赛比赛需 O(G) 时间。剩余比赛共有 3^r 个结果序列；每个序列复制四队积分、处理 r 场并比较三个对手，需 O(r+4) 时间，总计 O(G+(r+4)×3^r)。最大搜索只有 3^6=729 个序列，每个至多处理六场，非常小。

输入记录、未赛列表、积分表和 product 当前生成的结果共占 O(G+r+4) 空间；没有保存全部结果，因而空间不是 O(3^r)。四队且最多六场的本题中，实际只需几个很小的列表与元组。

容易出错的地方

  • 输入的 SA、SB 是比分，不是积分。它们只决定给谁 3 分或双方各 1 分。
  • 目标队必须严格超过每个对手。使用 ≥ 会把并列冠军误算进去。
  • 每次枚举都要从相同的已赛积分重新开始，不能让前一个组合的积分残留。
  • 也要枚举不涉及目标队的比赛；那些比赛会改变对手积分，可能决定谁是冠军。
  • 未赛的每场都需要胜、负、平三种结果。只枚举两种胜负会漏掉平局。
  • 数的是积分结果组合，不是具体比分或概率；比分无限多，但每场只有三种需要计数的结果。

Python 3 解法

solution.py
from itertools import combinations, product


def count_championships(favorite, games):
    points = [0] * 5
    played = set()
    for a, b, score_a, score_b in games:
        played.add((a, b))
        if score_a > score_b:
            points[a] += 3
        elif score_b > score_a:
            points[b] += 3
        else:
            points[a] += 1
            points[b] += 1
    remaining = [pair for pair in combinations(range(1, 5), 2)
                 if pair not in played]
    answer = 0
    for outcomes in product(((3, 0), (0, 3), (1, 1)), repeat=len(remaining)):
        final = points.copy()
        for (a, b), (add_a, add_b) in zip(remaining, outcomes):
            final[a] += add_a
            final[b] += add_b
        if all(final[favorite] > final[team]
               for team in range(1, 5) if team != favorite):
            answer += 1
    return answer


if __name__ == '__main__':
    favorite = int(input())
    completed = int(input())
    games = [tuple(map(int, input().split())) for _ in range(completed)]
    print(count_championships(favorite, games))

Problem statement (English)
Problem S3: Chances of winning
Problem Description
You want to determine the chances that your favourite team will be the champion of a small tour-
nament.
There are exactly four teams. At the end of the tournament, a total of six games will have been
played with each team playing every other team exactly once. For each game, either one team wins
(and the other loses), or the game ends in a tie. If the game does not end in a tie, the winning team
is awarded three points and the losing team is awarded zero points. If the game ends in a tie, each
team is awarded one point.
Your favourite team will only be the champion if it ends the tournament with strictly more total
points than every other team (i.e., a tie for first place is not good enough for your favourite team).
The tournament is not over yet but you know the scores of every game that has already been played.
You want to consider all possible ways points could be awarded in the remaining games that have
not yet been played and determine in how many of these cases your favourite team will be the
tournament champion.

Input Specification
The first line of input will contain an integer T which is your favourite team (1 ≤ T ≤ 4).
The second line will contain an integer G, the number of games already played (0 ≤ G ≤ 5).
The next G lines will give the results of games that have already been played. Each of these lines
will consist of four integers A, B, SA , SB separated by single spaces where 1 ≤ A < B ≤ 4,
and SA , SB ≥ 0 . This corresponds to a game between team A (which had score SA ) and team
B (which had score SB ) where team A won if SA > SB , team B won if SA < SB and the game
ended in a tie if SA = SB . The pairs A and B on the input lines are distinct, since no pair of teams
plays twice.

Output Specification
The output will consist of a single integer which is the number of times that team T is the champion
over all possible awarding of points in the remaining games in the tournament.

Official problemPDFDMOJ

What are we asked to do?

Four teams each play every other team once. Given completed games, count the combinations of wins, losses, and ties in the remaining games that make the favorite finish strictly above all three opponents. The required output is a count, not a probability.

Knowledge and skills

  • Game scores and tournament points are different. A 100:99 win still gives only 3 tournament points to the winner and 0 to the loser. A 2:2 tie gives each team 1 point. Goals must not be added directly to the points table.
  • The unordered pairs of four teams are (1,2), (1,3), (1,4), (2,3), (2,4), and (3,4): six games. Order does not matter, so (1,2) and (2,1) describe the same game. combinations generates these six pairs, and we remove the completed games.
  • Each unplayed game has exactly three point outcomes: (3,0) for the first team winning, (0,3) for the second winning, and (1,1) for a tie. Two games give 3×3=9 combinations; r games give 3^r. Enumeration checks every complete combination rather than guessing the most helpful results.
  • A Cartesian product chooses one item from each group of choices to form all possible combinations. Two groups of win/loss/tie choices produce nine pairs of results. Python's product(..., repeat=r) generates complete r-game outcomes one at a time, without storing all 3^r combinations at once.
  • Strictly first means the favorite has more points than every opponent. If the favorite and another team both have 7 points, the favorite is not champion even when the other teams have fewer. all(...) checks that all three comparisons hold.

Think step by step

  1. Read favorite T and the G completed games. Initialize points for teams 1 through 4 to zero; array index 0 is unused.
  2. Compare SA and SB for each completed game. Give the winner 3 points, or give both teams 1 for a tie. Record the completed team pair.
  3. Generate all six pairs of teams and exclude the completed ones, leaving r=6−G unplayed games.
  4. Use product to enumerate all combinations of (3,0), (0,3), and (1,1) for those games. Copy the completed-game points for every combination so different combinations cannot affect each other.
  5. Add the chosen points for each remaining game to that copy. Compare the favorite with each of the other three teams and add 1 to the answer only if all three strict comparisons succeed.
  6. After all combinations have been checked, print the count. Different actual scores with the same win/loss/tie result are one point outcome and must not be counted separately.

Walk through an example

In sample 2, teams 1, 2, 3, and 4 currently have 1, 2, 6, and 1 points. The remaining games are (1,4) and (2,3). Even if teams 1, 2, or 4 win their last games, they can finish with at most 4, 5, or 4 points. Favorite team 3 keeps at least 6 even if it loses. Thus all 3×3=9 combinations make it champion, and the answer is 9.

For another example, suppose only (1,2) remains, the points are [6,6,1,1], and team 1 is the favorite. A team-1 win gives [9,6,1,1] and counts once. A team-2 win does not make team 1 champion. A tie gives [7,7,1,1], which also fails because first place is shared. The answer is 1.

Why does this work?

First, comparing the actual scores and awarding 3 points to the winner or 1 to each team correctly computes the points from completed games. Since every pair plays once, generating all six pairs and excluding completed games leaves exactly the unplayed games.

Second, every unplayed game has exactly one of the three point outcomes. product chooses one for each game and generates each complete sequence exactly once, with no omissions or duplicates. Starting with a copy of the completed-game points and adding each chosen award computes precisely the final points for that sequence. Copying prevents points from another sequence from carrying over.

Finally, the favorite strictly exceeds all three opponents if and only if it is the unique team with the highest total. The program counts only when all three comparisons hold, excluding every tie for first. Since every possible sequence is checked exactly once, the accumulated count is exactly the requested number of championship outcomes.

Time and memory

Let r=6−G≤6. Processing completed games takes O(G) time. There are 3^r remaining-game outcome sequences. Each copies four teams' points, processes r games, and checks three opponents, taking O(r+4) time. Total time is O(G+(r+4)×3^r). The largest search has only 3^6=729 sequences, each processing at most six games.

The input records, remaining pairs, points, and current product tuple require O(G+r+4) space. All combinations are not stored, so space is not O(3^r). With just four teams and six games, these are only a few small lists and tuples.

Common mistakes

  • SA and SB are game scores, not tournament points. Use them only to decide who earns 3 points or whether both teams earn 1.
  • The favorite must strictly beat every opponent. Using ≥ would incorrectly count shared first place.
  • Restart every combination from the same completed-game points; do not carry over awards from the previous combination.
  • Enumerate games that do not involve the favorite too: they affect opponents' totals and can determine the champion.
  • Every unplayed game needs three outcomes, including a tie. Considering only wins and losses misses valid combinations.
  • Count point-outcome combinations, not exact scores or probabilities. There are infinitely many possible scores but only three relevant outcomes per game.
